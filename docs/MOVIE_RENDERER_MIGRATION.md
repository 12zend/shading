# Movieの直接描画経路

Objectsの描画は `prepareMovieSource` でrenderer所有のリソースを用意し、`drawMovieTexture` で現在の描画先へ合成する。スプライトのコスチューム変更、BitmapSkinの新規作成、`penStamp` は経由しない。

- shape / line: renderer内でラスタライズし、不変テクスチャをキャッシュする。
- text: renderer内で文字をラスタライズし、フォント・文字列ごとのテクスチャを共有する。
- video: VMが時刻指定・デコードを管理し、rendererが描画する。同サイズの更新は `texSubImage2D` で領域を再利用する。
- model: rendererがThree.jsで3Dをラスタライズし、結果を現在のバッファへ合成する。読み込み済みモデルは同期実行する。
- costume: 既存のコスチュームテクスチャを直接参照する。SVGはrendererの最大テクスチャ寸法内で最大のキャッシュ解像度を選び、表示サイズによる低解像度への切り替えを行わない。ビットマップは元画像を使う。スプライトの通常表示の解像度選択は変更しない。

描画先のフレームバッファをリソース生成時に保存せず、描画のたびにrendererが所有する現在のMovieBufferから取得する。グループの隔離バッファ、フレームの作業バッファ、Pen FXの描画領域追跡を共有する。直接描画が画面へフレームを公開することはなく、公開・取消は既存フレームトランザクションが担当する。

旧VM側の3D実装・中継ファイル、GUI側のmodel-runtime中継、Objectsの旧shapeスキンキャッシュは削除した。Looksブロックで明示的にスプライトの見た目を変更する機能は維持する。Pen拡張、PenSkin、旧penStamp/penLine/penPoint/penClear API、標準拡張の読み込み処理は削除した。

Canvas 2Dによるshape/line/textのラスタライズと、Three.jsの別WebGLコンテキストからの画像転送は残る。3D色・深度パスの単一化実験は画像互換性を十分に検証できず、採用していない。

比較したshape・line・textのケースでは旧経路と画像ハッシュが一致した。3Dの初回ネイティブ測定は旧経路も空画像だったため、3Dの画像互換性・速度改善の証拠として使用しない。全種類の速度向上を保証する結果は得られていない。

## Pen削除後の互換性と所有権

- バッファ作成と表示用drawableは `RenderWebGL.getMovieBufferId()` が所有する。VMにレイヤーIDは保持しない。
- 消去、現在のスプライトの描画はObjectsカテゴリーから利用する。旧 `pen_*` opcodeは読み込み互換用の名前としてのみ残り、VMのMovie命令を通じて同じrendererへ渡す。Pen拡張は読み込み・保存・UI登録のいずれでも使わない。
- 旧プロジェクトの軌跡はMovieDrawTargetの解析的な線ラスタライザーで描画する。連続した軌跡を256本単位でまとめ、図形・消去・グループ・エフェクト・フレーム切り替えの前に送信する。WebGL1の非インスタンシング環境にも対応する。
- 軌跡用GPU属性バッファは利用時のみ作り、インスタンシング対応環境では10 KiB。旧PenSkinは利用の有無によらず約640 KiBを確保していた。
- Pen FXはエフェクトの既存opcode・カテゴリー名として維持するが、描画先はMovieBuffer。Pen拡張への依存はない。

検証では、旧プロジェクトの読み込み・保存、実VMのコンパイル／インタープリターでの消去→描画→後続命令の同期実行、グループ／フレームの確定・取消・GPUバッファ再利用を確認する。

ネイティブOpenGLでshape 1000回は中央値48.01 ms（旧測定56.72 ms）、画像ハッシュ一致、GLエラーなし。旧軌跡100本は0.46→0.51 msで画像ハッシュ一致、GLエラーなし。実行環境によるばらつきがあり、これを全機能の高速化とは解釈しない。逐次100回のGPU送信で発生した軌跡の退行はまとめ描きで解消した。
